# Ekylibre 5.0 — Notes de version

**Date de sortie :** 27 juin 2026
**Version précédente :** 4.35.0

Bienvenue dans Ekylibre **5.0**, une version majeure tournée vers la conformité réglementaire 2027, l'assistance intelligente au quotidien, et une nouvelle expérience d'administration de la plateforme.

> Cette page s'adresse aux utilisatrices et utilisateurs de l'application : agriculteurs, conseillers, technicien·ne·s, et gestionnaires de la plateforme. Pour le détail technique, voir [`CHANGELOG.md`](../../CHANGELOG.md).

## En un coup d'œil

- 🌱 **HVE** — module d'audit Haute Valeur Environnementale (HVE3), thème **Biodiversité** opérationnel, thèmes Phytosanitaire / Fertilisation / Irrigation livrés via le plugin `ekylibre-hve`.

## 🌱 HVE — Audit Haute Valeur Environnementale

Vous pouvez désormais préparer votre audit **HVE3** directement depuis Ekylibre.

**Ce qui est nouveau :**

- Un audit HVE par campagne, avec quatre thèmes :
  - **Biodiversité** (mode opérationnel)
  - **Stratégie phytosanitaire** (livré via plugin `ekylibre-hve`)
  - **Fertilisation** (livré via plugin)
  - **Gestion de l'irrigation** (livré via plugin)
- Chaque thème doit atteindre **au moins 10 points** pour valider l'audit (règle « tout ou rien »).
- **Inventaire IAE** (Infrastructures Agro-Écologiques) : haies, bandes enherbées, mares, prairies permanentes…
  - Surface ou linéaire saisi, équivalent hectare calculé automatiquement (Annexe 1, Plan HVE V4.4).
- **Items biodiversité** (8 critères, §4.1 à §4.8) : % d'IAE, taille des parcelles, poids des cultures principales, diversité variétale et animale, races et variétés menacées, qualité du sol.
- **Détection automatique CMR1** : l'utilisation d'un produit phytosanitaire classé CMR1 sans dérogation bloque l'audit complet.
- **Reprise des IAE d'une année sur l'autre** : un bouton « Cloner depuis l'année précédente » évite la double saisie.

**Comment y accéder :** menu *Activités* → *Audits HVE*.

**Données de référence vendorisées** (mises à jour annuellement via `rake hve:reference:load`) :

- Coefficients IAE (Plan HVE V4.4).
- Exports d'azote par culture (Comifer 2013).
- Tables IFT régionales (seuils Pc / Pf).
- Snapshot annuel des AMM classés CMR1 / CMR2.

## 📋 Registre phytosanitaire 2027

L'**Arrêté du 24 décembre 2025** impose un nouveau format de registre des traitements phytosanitaires. Ekylibre 5.0 le produit automatiquement.

**Ce que vous obtenez :**

- Une page dédiée **Registre phytosanitaire** (menu *Suivi cultural* → *Registre phyto*).
- **Sélection par campagne** et prévisualisation des entrées avant export.
- **Validation d'intégrité** : Ekylibre vérifie les 9 champs obligatoires (SIRET, produit, AMM, date, dose, surface traitée, culture, géométrie de la parcelle…) et liste les erreurs avant export.
- **Trois formats d'export** :
  - **XML** au schéma officiel `urn:fr:agri:phyto:register:1.0`.
  - **JSON** conforme à la directive européenne 2019/1024.
  - **CSV** pour ouverture dans tableur.
- **Archivage légal** :
  - Le registre est stocké comme document Ekylibre, signé par empreinte **SHA-256**.
  - Conservation automatique de **5 ans et 1 mois** (champ `legal_retention_until`).
  - Une tâche automatique **chaque 31 janvier** archive le registre de l'année écoulée pour toutes les fermes françaises.

**Nouveaux champs sur l'intervention phytosanitaire :**

- **Conditions météo** au moment du traitement : température, vent, humidité, code météo (vue OpenWeatherMap).
- **Réentrée anticipée** (oui/non), avec description des EPI portés et motif.
- **SIRET du bénéficiaire** (sur les interventions de prestation), validé à 14 chiffres.

**Performance — bug #2648 corrigé :** la fiche d'intervention phytosanitaire ne lague plus lorsqu'elle cible plus de 10 parcelles ou plantes (chargement en une requête au lieu de N requêtes).

## 🤖 Duke — votre assistant agricole

**Duke** est un assistant conversationnel intégré au logiciel. Il apparaît sous forme de **bulle flottante en bas à droite** dans chaque écran du backend.

**Ce que Duke sait faire :**

- **Dialoguer** en français : posez-lui une question sur votre ferme, demandez-lui de préparer une intervention.
- **Dicter une intervention à la voix** :
  - Reconnaissance vocale directement dans le navigateur (Web Speech API), pas d'envoi de votre voix sur le serveur sauf si nécessaire.
  - Repli automatique sur un serveur Whisper si votre navigateur ne supporte pas la dictée (Firefox, mobile).
- **Brouillons d'interventions structurés** : à partir de ce que vous dites (« j'ai semé du blé tendre sur la parcelle Verbiac hier de 8h à 12h »), Duke construit une carte récapitulative avec :
  - la procédure suggérée,
  - les périodes de travail,
  - les parcelles et plantes ciblées,
  - les intrants (produits, doses),
  - les outils et opérateurs.
- **Levée d'ambiguïté** : si plusieurs parcelles ou produits correspondent à votre description, Duke vous propose des **puces de choix** (sélection simple ou multiple) avant validation.
- **Validation en un clic** : un seul bouton crée l'intervention dans Ekylibre via l'API v2.

**Choix du moteur d'IA :** un sélecteur dans l'en-tête de Duke vous permet de basculer entre :

- **Claude** (Anthropic)
- **Mistral** (cloud)
- **Ollama** (modèle local hébergé sur votre serveur)

Le mode **Ollama local** permet d'utiliser Duke **sans envoyer vos données sur Internet** — utile pour les exploitations avec contraintes de confidentialité.

**Documentation :** voir `docs/api/README.md` pour l'intégration et `docker/prod/README.md` pour le déploiement.

## 🛠 Console d'administration `/admin`

Une nouvelle interface dédiée à la gestion **multi-fermes** est disponible à l'adresse `/admin` (authentification HTTP Basic).

**Ce que vous pouvez faire :**

- **Lister toutes vos fermes** (tenants) avec leur état, leur taille en base et leurs archives.
- **Créer une nouvelle ferme** depuis un formulaire (nom, email, mot de passe, langue, pays, devise) — l'initialisation tourne en arrière-plan avec une barre de progression en **16 étapes** (base, comptabilité, lexique, etc.).
- **Envoyer automatiquement les identifiants** par email à la création.
- **Supprimer une ferme** (avec sécurité : les noms `admin`, `duke`, `traccar`, `ekylibre` sont réservés).
- **Charger une démo** dans une ferme existante, en un clic, avec suivi de progression.
- **Restaurer une ferme** depuis une archive zip téléversée.
- **Gérer le lexique agricole** :
  - Lister les versions disponibles,
  - Télécharger anonymement les versions ≥ 6.0.2,
  - Activer ou supprimer une version installée.
- **Voir les plugins installés** : version d'Ekylibre + liste de chaque plugin (nom, branche, révision Git, version gem).

**Nouvelle page d'accueil publique** : la racine du domaine (sans sous-domaine) présente désormais une **landing page** moderne avec présentation des modules Ekylibre, accès rapide à l'administration et illustrations de la plateforme.

## 🌐 API v2 — nouveaux endpoints

L'API v2 s'enrichit pour les intégrations mobiles, les outils tiers et les clients externes (comme Duke).

**Nouveaux endpoints :**

| Endpoint | Usage |
|---|---|
| `GET / POST / PUT /api/v2/cultivable_zones` | CRUD parcelles avec **géométrie GeoJSON** (champ `shape_to_geojson`) — exploitable dans QGIS, applis cartographiques mobiles, intégrations SIG. |
| `GET / PUT /api/v2/profile` | Lecture / mise à jour du profil utilisateur. |
| `GET /api/v2/users/me` | Profil minimal pour clients externes. |
| `POST / DELETE /api/v2/tokens` | Authentification et révocation de jetons. |
| `GET /api/v2/products[/:type]` | Catalogue produits par type (animal, ouvrier, équipement, parcelle, division bâtiment, plante, matière) avec filtre `modified_since`. |
| `GET /api/v2/variants` | Variantes de nature de produit. |
| `GET /api/v2/procedures` | Catalogue des procédures Procedo avec arbre de paramètres. |
| `GET /api/v2/farm_profiles/:year` | Profil annuel agrégé : info générale, météo, biodiversité, rotations (année + 2 antérieures). |
| `GET /api/v2/farm_accountancy/:year` | Bilan annuel : ratios globaux, comptabilité, indicateurs économiques. |

**Améliorations sur les interventions :**

- **CRUD complet** avec graphe imbriqué (périodes de travail, intrants, sorties, outils, cibles, opérateurs, lectures).
- **Idempotence** : la création utilise un triplet `(vendor, name, id)` côté fournisseur — vous pouvez rejouer une requête sans créer de doublon.
- **Nouveaux filtres** : `contact_email`, `user_email`, `with_interventions`, `nature`, `provider_id`.

**Lexique phytosanitaire** (`cropsets`, `products`, `risks`, `usages`) :

- Pagination disponible (`paginate`, `page`, `per_page`).
- `POST` retourne un **diff `{ removed, updated }`** pour synchroniser un cache client efficacement.

**Documentation :**

- Spécification **OpenAPI 3.0** complète : `docs/api/openapi-v2.yaml` (1 028 lignes, lisible dans Swagger UI / Redoc / Postman).
- Guide d'intégration en français : `docs/api/README.md`.

Les plugins sont visibles depuis la console `/admin` (nom, branche, révision Git, version gem).

Ces plugins ne sont **pas inclus** dans l'image GHCR publique et nécessitent un `Gemfile.local` séparé :

| Plugin | Rôle |
|---|---|
| **ekylibre-imepe** | Connecteur **MesParcelles** (Chambres d'Agriculture) : import des parcelles et historiques culturaux. Sous licence propriétaire (≥ Ekylibre 3.30.0). |

### Activer un plugin en développement

Ajouter dans `Gemfile.local` du dépôt principal :

```ruby
gem 'ekylibre_hve', path: '/ekylibre-plugins/ekylibre-hve'
```

Puis dans le conteneur app :

```bash
bundle install
rake tenant:migrate TENANT=<nom_tenant>
```

Pour les plugins HVE/IDEA, charger aussi les référentiels :

```bash
TENANT=<nom_tenant> rake hve:reference:load
```

### Activer un plugin en production

Les plugins publics sont déjà déclarés dans `docker/prod/Gemfile.prod`. Pour ajouter un plugin privé, créer un `docker/prod/Gemfile.local` et rebuilder l'image. Le workflow CI gère la résolution Bundler automatiquement.

## 📱 App mobile — Zero Mobile

Ekylibre 5.0 s'accompagne d'une **nouvelle application mobile** : `zero-mobile`, distribuée en parallèle de la sortie 5.0 via **TestFlight** (iOS) et **Google Play Internal Testing** (Android).

> **Statut :** version pilote (v0.1.0), périmètre v1 ciblé sur la **boucle pulvérisation hors-ligne → synchro fiable**. Distribution publique sur les stores conditionnée aux retours des fermes pilotes.

### Pour qui ?

- **Profil principal v1 :** agriculteur exploitant, francophone, saisissant ses propres interventions sur le terrain.
- UX épurée, vocabulaire métier en français, charge cognitive faible.
- Pas de profil technicien itinérant en v1 (multi-comptes différé en v2).

### Ce que l'app sait faire

- **Connexion à votre instance Ekylibre** — saisie de l'URL (cloud ou on-premise), email, mot de passe. Authentification via `POST /api/v2/tokens`. Token stocké dans le **Keychain iOS** / **Keystore Android** (jamais en clair).
- **Synchronisation initiale du catalogue** (au premier login) :
  - Procédures (`GET /procedures`)
  - Produits (ouvriers, équipements, intrants, etc. via `GET /products?product_type=...`)
  - Parcelles cultivables (`GET /cultivable_zones` avec géométrie GeoJSON)
  - Variantes (`GET /variants`)
  - Reprise transparente en cas d'interruption.
- **Saisie d'une pulvérisation 100 % hors-ligne** :
  - Sélection d'une parcelle, ajout d'un ou plusieurs produits phytosanitaires (variant + dose + handler), choix du pulvérisateur, du ou des opérateurs, des dates / durées, notes libres.
  - **Validation locale stricte** : cardinalité et champs requis de la procédure `spraying` vérifiés *avant* sauvegarde — impossible d'enregistrer une intervention incomplète.
  - **Pré-remplissage intelligent** des unités et handlers depuis le catalogue.
  - **Filtrage des équipements** par capacité réelle (`abilities`) — le sélecteur Pulvérisateur n'affiche que les outils marqués `can spray` côté Ekylibre.
- **Carte interactive des parcelles** (MapLibre + tuiles OpenStreetMap) :
  - Affichage des polygones de votre catalogue local.
  - Sélection multi-cibles directement depuis la carte.
  - **Précache hors-ligne** des tuiles OSM par bbox + 5 km — la carte reste utilisable au champ, sans réseau.
- **Synchronisation manuelle** :
  - Un bouton **Synchroniser** pousse les interventions locales vers Ekylibre via `POST /api/v2/interventions`, puis tire les changements distants.
  - **Idempotent par UUID client** — vous pouvez taper « Synchroniser » plusieurs fois sans créer de doublon côté serveur.
  - Les erreurs serveur sont attachées à l'intervention concernée (badge **erreur de sync** avec message lisible), sans bloquer le reste du lot.
- **Hors-ligne complet** après le premier login — toutes les fonctions restent utilisables sans réseau.

### Stack technique

| Domaine | Choix |
|---|---|
| Framework | **Expo SDK 55** (Development Build ; Expo Go non supporté) |
| Routage | **Expo Router v6** (file-based) |
| Langage | **TypeScript strict** (`noUncheckedIndexedAccess`) |
| Base locale | **WatermelonDB** (SQLite + JSI, offline-first) |
| Cartographie | **MapLibre Native** + tuiles OSM raster (cache offline natif) |
| Formulaires | **React Hook Form** + **Zod** |
| Sécurité | **expo-secure-store** (Keychain / Keystore) |
| i18n | **i18next** (FR seul en v1, architecture multilingue prête) |
| Crash reporting | **Sentry** |
| Runtime | **Node 24** + **pnpm 10** |
| Distribution | **EAS Build** (iOS + Android) |

### Bundles

- **iOS** : `com.ekylibre.zeromobile` (TestFlight)
- **Android** : `com.ekylibre.zeromobile` (Internal Testing — Play Console)

### Côté Ekylibre 5.0 — ce que l'app utilise

L'API v2 livrée dans 5.0 contient **exactement ce dont l'app a besoin** :

- `POST /api/v2/tokens` (auth)
- `GET /api/v2/procedures` (catalogue procédures + arbre de paramètres)
- `GET /api/v2/products[/:type]` et `GET /api/v2/variants` (catalogue)
- `GET /api/v2/cultivable_zones` (parcelles avec `shape_to_geojson`)
- `POST /api/v2/interventions` (création **idempotente** via `provider: { vendor: "zero-mobile", id: <UUID>, ... }`)

Aucun changement côté Ekylibre n'est nécessaire pour activer Zero Mobile : il suffit que votre instance soit en 5.0 (ou ultérieure) et accessible en HTTPS.

### Critères « v1 livrée »

L'app sera officiellement livrée quand un build aura été :

1. Distribué via **TestFlight** + **Internal Testing Play**.
2. Mis aux mains d'un panel pilote d'agriculteurs Ekylibre.
3. Capable de jouer le scénario complet (login → sync initiale → saisie pulvé hors-ligne → sync → vérification web) chez **≥ 3 fermes pilotes différentes**.

Le passage en stores publics (production) est explicitement **hors v1** et conditionné aux retours du panel.

## ⚙️ Pour les administrateurs système

Cette section décrit les changements à connaître avant de déployer 5.0 en production.

### Changements impactants

- **Serveur web** : passage de **Unicorn** à **Puma 5.6** en production. Multi-workers, configuration dans `config/puma.rb`, à régler via `WEB_CONCURRENCY`.
- **Node.js minimum requis : 20** (était 14). La compilation des assets continue d'utiliser `--openssl-legacy-provider` en repli.
- **Lexique** : version épinglée `6.0.2-innovation`. Exécuter `rake lexicon:load` après mise à jour.
- **Proxy inverse** : Nginx remplacé par **Caddy** en production avec **TLS à la demande** par sous-domaine. Multi-tenant Let's Encrypt fonctionne désormais nativement.
- **Plugins** : en production, les plugins sont résolus depuis `docker/prod/Gemfile.prod` (forks publics `github.com/ekylibre/*`). Le workflow CI force Bundler à utiliser la tête de branche.
- **`docker/db/init.sql`** : un garde `IF EXISTS` est ajouté autour de `DROP EXTENSION postgis`. **Si vous avez une copie ancienne de ce fichier, remplacez-la** — l'ancien script supprimait silencieusement toutes les colonnes géométriques à chaque redémarrage du conteneur PostgreSQL.
- **Noms de tenants réservés** : `admin`, `duke`, `traccar`, `ekylibre` ne peuvent plus être créés depuis la console.
- **AgroMonitoring** sort du cœur et devient un plugin séparé. Si vous utilisiez cette intégration satellite, installez le plugin correspondant.

### Nouveautés infra

- **Stack Docker prod réécrite** autour de Dokploy :
  - `docker/prod/docker-compose.yml`, `docker-compose.dokploy.yml`.
  - Images publiées sur GHCR : `ghcr.io/ekylibre/ekylibre/app:<tag>`.
  - `pull_policy: always`, webhook Dokploy déclenché par CI après publication d'image.
- **CI** : `.github/workflows/build-prod-image.yml` construit sur push vers `5.0-beta`, `main`, et tout tag `v*`.
- **Sidekiq** attend désormais le healthcheck applicatif avant démarrage (évite le chargement de modèles avant que le lexique soit prêt).
- **Documentation prod** :
  - `docker/prod/README.md` — guide de déploiement.
  - `docker/prod/DOKPLOY.md` — variante Dokploy.
  - `docker/prod/GPG.md` — clés GPG pour signature de documents.
  - `docker/prod/.env.dist` — modèle de configuration (170 variables).
  - Scripts utilitaires : `duke-up`, `duke-update`, `lexicon-reload`, `tenant-*.sh`.
- **Développement** : `dnsmasq` ajouté au compose dev pour résolution DNS locale multi-tenant (`*.localhost`).

### Stack Duke

Si vous activez Duke en production, déployez ces services additionnels :

- `duke-api` — serveur WebSocket + STT (image `ghcr.io/ekylibre/duke/duke-api:<tag>`).
- `postgres-duke` — base PostgreSQL 16 dédiée à l'état de Duke.
- `ollama` + `ollama-pull` — moteur LLM local (par défaut Mistral Nemo, configurable via `OLLAMA_MODEL`).
- `nanoclaw` — pont Telegram → Duke → Ekylibre (optionnel).

Configurez le rôle PostgreSQL en lecture seule :

```bash
docker compose exec app bundle exec rake duke_reader:grant_tenants
docker compose exec app bundle exec rake duke_reader:verify
```
